## 研究发现

### A1 · 公开铁路拟合用错了模拟日期对应的观测

降雨模型要验证某一天的延误，至少需把同一天的模拟、降雨和真实延误连起来。Faccin、Scagliarini 与 De Domenico 的铁路论文报告了以 2024 年为外测的超额延误关联。复查作者公开仓库的固定提交时，能在另一条用于 2021–2023 年拟合的路径上证明日期配对不一致。这个路径还把验证损失交给网格搜索与 Nelder–Mead 优化，运行时错配会进入择参目标。[铁路论文与固定代码位置](../../content/sources/paper-climate-transport-collapse.md#validation-input-audit)

问题发生在模拟结果交给评分函数时。拟合脚本先在按雨量分层的测试折中逐日模拟，再把结果依次配给全体日期的排序表。评分用配到的日期选择下雨站点及当天真实超额延误。两条日期序列只要有一个位置不同，该位置的比较就不再是同一天。

公开雨峰表提供了一个无需重跑模型的检验。2021–2023 年共有 1095 个日期，按代码规则 `rain > 500` 分层，其中 20 个属于高雨类。四折分层使每个测试折有 5 个高雨日。评分却取全表开头的同样长度，前 273 或 274 天都只有 4 个高雨日。因此两列日期不可能逐位相同，至少一条结果被交给了另一日期。显式保留日期和模拟结果的配对，连空模拟结果也沿用输入日期，就能在进入损失计算前检验这个连接。这里的计数是对固定表和代码的静态核查，尚未测量纠正后损失或参数变化。[固定雨峰表与函数](../../content/sources/paper-climate-transport-collapse.md#validation-input-audit)

还需对齐的是传播算子。拟合入口按边上的列车流量加权，稳态入口读取拟合系数后按默认等边权传播。论文的 2024 验证另有公开入口，读取缓存参数。仍需作者实际使用的缓存、原始雨量网格、代码与输出记录，才能把公开入口的差异对应到论文结果。这次增加的是复验时可优先核对的两个对象：逐日比较的身份，以及系数所对应的传播算子。[验证配对与算子说明](../../content/notes/transport-delay-propagation-and-thresholds.md#validation-pairing)

### B1 · 旧 KV 可缩短首 token 等待，跨版本服务对照仍有输出分歧

模型升级后能否接着使用旧缓存，首先取决于新模型如何读旧模型编码出的历史。相同 token、位置和缓存形状使状态有机会被接入，但新旧权重通常为同一历史产生不同状态。Tao、Jin 与 Zhao 的新预印本在固定目标权重、输入 token 和 greedy 解码时，用目标自己计算历史作基准，再让目标读取旧状态并处理同一问题。32K 针测以 8 个历史中的 192 条查询比较每对权重。V4.1-Flash → 1017 两组答案前缀正确率均为 97.92%，Qwen3-30B-A3B → Instruct-2507 即使做了位置对齐也从 55.21% 降到 13.02%。两对配置的差距表明，能接入缓存之后仍需按实际升级方向验证任务。[Tao 等 v1，§2、§3.1 和表 1](https://arxiv.org/html/2611.14051v1#S3.SS1)

另一组问答服务实验在 V4-Flash → 0731 上使用已经准备好的旧状态。引擎加载文件后端中完整的 256 token 页，由目标重算没有对齐的尾部。作者用每个有效配对的“冷算首 token 时间除以复用首 token 时间”，再取中位数。时间含查找、加载、恢复和剩余计算，排除旧状态预填及启动。在 MultiFieldQA-en 上，该比值为 2.51，token 级 F1 从 45.9 到 46.2。HotpotQA 首 token 时间比为 5.08，但 F1 从 69.3 降到 66.3。较短的 BABILong 比值为 0.86，意味着复用反而慢。这三个结果分别说明任务分数、被省下的计算和缓存装载成本会共同决定结果。[Tao 等 v1，§3.2 与附录 A.2、B、C.1](../../content/sources/paper-kv-cache-across-model-updates.md)

MultiFieldQA-en 的均分接近，也不等于答案保持一致。80 个成功有效配对中，70 个首 token 相同。其中 37 个后来分歧，33 个完整记录相同。权重之外，交接路径本身也可能影响结果。作者让目标模型把自己生成的缓存沿交接路径恢复，在这一诊断的 85 个配对中仍只有 52 个全文相同。两组分母不同，不能用相减估算多少分歧由权重单独造成。[Tao 等 v1，§3.4、附录 C.3 与 C.4](../../content/sources/paper-kv-cache-across-model-updates.md)

此前的精确缓存条件说明何时可沿用原计算。这里增加了近似移植的验收方法：在同一升级方向分别测首 token 成本、任务得分和行为一致，并加入同版本恢复来定位交接影响。它也给出一个比较路由方案的基准，若改由目标模型自己提前算历史，误差来源和资源账都会变。[跨权重复用解释](../../content/notes/kv-cache-mechanism.md#cross-checkpoint-reuse)

### C1 · 两色同键分开了反应选择，平均时差仍不能分解心理过程

看到蓝色墨水写的“红”并报告墨色时，词义与颜色不同，二者也分别指向不同口头反应。若给两种颜色分配同一个键，就能保留词义与颜色的差异，同时让它们指向同一动作。Hasshim 与 Parris 2014 年的实验用这种安排研究，按键不冲突时，词义与墨色不一致是否仍会拖慢反应。[2014 年原文，引言、方法与实验 2](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2014.01157/full)

例如把蓝和绿分到左键，红和黄分到右键。绿墨写“蓝”时，两种颜色都指向左键。若同色、异色同键、异色异键三种试次等量，读到“蓝”就可用三分之二的概率猜左键。实验 2A 把异键试次加到两倍，覆盖右键的两种墨色。给定同一个颜色词，两键成为正确反应的概率各为一半。研究者还加入非颜色词作基线，这样中性对照不会把词义和墨色本身相同的促进当作比较起点。[2014 年原文，试次构成](../../content/sources/paper-stroop-two-to-one-mapping.md#evidence)

实验 2 有 36 名学生。按实验 2A 的筛选口径，使用正确且 200–2500 ms 的反应，同键与中性的均值分别为 602.35 和 601.55 ms，异键为 633.31 ms。将点零差与正向 6–45 ms 的均匀备择比较，同键对中性的贝叶斯因子为 0.17，在指定模型下偏向零差。实验 2B 以不属于响应集合的颜色词换掉同色同词条件。同样比较得到 0.58，作者视为难以区分。两个数值衡量的是给定备择下的平均差，范围没有覆盖所有可能大小的效应。[2014 年原文，实验 2A、2B 结果及脚注 1](../../content/sources/paper-stroop-two-to-one-mapping.md)

平均差的局限来自同键试次本身。作为 AI 说明性算例，若词义竞争使反应延长 15 ms，而指向正确键的第二个线索使反应缩短 15 ms，净差为零。两种作用都为零也给出同样的净差。算例只说明机制识别的歧义，原实验没有估计这两个分量。后续 Burca 等的修改设计报告了语义冲突的证据，本处只采用题录与摘要。旧 Stroop 说明任务怎样定义观察量，这次加入了一个具体的识别边界：先拆开词义冲突和按键冲突，再检查按键促进是否仍混在净差中。[机制解释与后续来源](../../content/notes/stroop-interference-and-experimental-controls.md#two-to-one-mapping)

### B2 · 让目标模型提前计算自己的 KV，收益取决于切换与普通流量

多轮代理在工具调用返回后可能切换模型。接收方若没有历史 KV，就要在回复前补算这段前缀。Qiu 等的 ShadowPrefill 把部分计算提前到有空余的时段，让可能接手的目标模型用自己的权重处理当前历史。切换时先复用留下的前缀，再计算新产生的尾部。若状态未留下，调用仍可冷启动。提前量越多，可能少等越久，也可能多算了最终用不到的状态。[Qiu 等 v1，§3](https://arxiv.org/html/2611.13176v1#S3)

预填和普通请求共用设备，因此空闲还需要从运行中的工作衡量。完整设计按普通请求的首 token 时间和逐 token 生成时延预留预算，出现排队便停发影子工作，并优先回收影子条目或将其转存主机内存。实机只实现较简单的请求级 Harvest，没有模拟策略中的逐迭代预算、专门影子优先驱逐和主机层。可以用实机判断请求级方案在实测负载中的表现，也可以用模拟比较完整策略的机制，两类结果有不同适用条件。[Qiu 等 v1，§3、§5 与 §6](../../content/sources/paper-shadowprefill.md)

§6 在总计 16 张 H100 的 vLLM 平台回放四组固定模型对和路由轨迹。校准容量取普通请求的首 token 与逐 token 时延均达标比例至少为 90% 的最高测试速率。普通流量为各组校准容量的 0.3 时，相对不做影子预填，切换调用的平均首 token 等待降 61.9%，每个任务内 LLM 调用耗时之和平均只降 7.0%。后者不计工具运行时间。SWE-agent-LM-7B 与 Qwen2.5-72B-Instruct 组只有 13% 的调用切换，且平均生成 249 token。切换调用首 token 等待降 65.9%，该组任务的 LLM 调用时间却几乎未变。能被提前的 prefill 只占整段调用中的一部分。[Qiu 等 v1，§6 与附录 D.1](../../content/sources/paper-shadowprefill.md#evidence)

同一实机方案也显示了更高负载下的风险。普通流量升到校准容量的 0.5 时，SWE-agent-LM-7B 与 SWE-agent-LM-32B 组合的全调用时延比无影子预填高 35.1%，两组 FusionBench 仍有收益。作者将变慢与运行中解码联系起来：队列即使没有待处理请求，当前解码迭代也可能被插入的预填拉长。这个反例把预取问题推进到服务竞争本身。用目标权重保持状态来源一致后，仍要在同轨迹下计切换等待、任务内总调用时间及普通请求所受影响。固定轨迹回放没有测新路由决策带来的任务成败。[目标模型预填的成本与适用条件](../../content/notes/kv-cache-optimization.md#routing-and-native-prefill)

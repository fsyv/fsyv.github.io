## 研究发现

### A1 · 缓存重新命中后，完整会话仍可能越积越多

突发结束后，控制策略可以让缓存重新有效，但积压的方向仍由会话到达与完成决定。Huang 与 Liu 的长会话试验中，缓存命中持续恢复，固定时间内到达的会话更常在截止前完成，系统内的未完成总数仍缓慢上升。三者对应计算效率、特定人群的交付和当前服务能否清掉历史欠账。 （Huang 与 Liu，2026 年 v1，§§5–6 指定正文）

会话每轮完成后还可能继续调用模型。若控制只拦住新会话，已经准入的会话仍在下一轮争用有限缓存。论文的预算器把活跃会话的当前上下文和预留输出相加，作为它们接下来可能占用的 KV 规模。账面需求超过池容量的 95% 时，刚到请求轮次边界的会话暂停，在途请求继续。等待队首计入后不超过 75% 时，允许再准入，已暂停会话优先。这个需求估计可以重复计入共享前缀，也只在轮次边界更新。控制通过缩小活跃工作集提供恢复机会，作者依据容量、命中和重算变化解释机制，未记录每块淘汰事件。 （预算器与证据口径）

第一次对照固定单张 MI300X、vLLM、Qwen3-8B、40 万 token 池和 25 轮的合成会话。基准每秒到达 0.04 个会话，第 10 分钟起有四分钟双倍到达，第 20 分钟启用控制，第 60 分钟截止。下表只用在所有控制臂均已陷入低命中的七个匹配种子。每个种子共用到达计划，开始控制时各臂在系统会话数和剩余轮次相近。恢复按宽五分钟、每分钟推进的窗口计算。首个按 token 加权命中率至少为 0.8 且以后各窗持续达标的窗口算作恢复，至少随访十分钟。“首窗内”表示这一个五分钟窗口达标。 （Huang 与 Liu，§6 匹配对照与 Table 3）

| 控制 | 恢复数 | 恢复时点 |
| --- | --- | --- |
| 预算器与轮次边界暂停 | 7/7 | 首窗内 |
| 经调参的会话数上限与暂停 | 7/7 | 六分钟以内 |
| 仅限制新准入 | 1/7 | 此处按匹配种子统计 |
| 无控制 | 0/7 | 观察窗内未恢复 |

这组对照指出，仅把新流量拦在系统外，通常不足以把已经挤入的工作集降下来。实验改变了暂停行为及其上限规则，支持比较整套控制的恢复效果。论文 Table 3 中仅限准入的 2/8 来自该臂所有已陷入运行，匹配结果用的是 1/7。两种分母对应各自的比较问题。

第二组 100 分钟试验把模型换为 Qwen3-32B，有约 36.5 万 token 池。工作负载按 SWE-bench 的长短与间隔合成重放，输入截断为 38K token，未执行实时代理任务。三个种子共用每秒约 0.025 个会话的基准设定，三倍突发持续五分钟，第 25 分钟开始控制。下面的完整会话完成率以控制后 20 分钟到达的会话为分母，判定它们是否在第 100 分钟前做完所有轮次。 （Huang 与 Liu，§6 长时异构负载）

| 控制 | 末十分钟 token 命中率 | 指定到达会话的截止完成率 |
| --- | --- | --- |
| 预算器与暂停 | 0.92–0.97 | 54%–96% |
| 自适应会话数上限与暂停 | 0.86–0.93 | 83%–97% |
| 无控制 | 0.12–0.13 | 0%–7% |

在两种控制下，总积压的末 30 分钟都仍以每十分钟约 4–8 个的速度增加，末五分钟平均仍有 73–101 个会话在排队或执行。作者观察到，缓存已经热起来的这一阶段，每分钟约有 1.5–1.6 个会话到达与 0.7–1.3 个完成。按 AI 的会话记账解释，每个到达都为未完成总数加一，每个完整完成减一，统计的是全部会话。表中的固定到达人群比例不能代入这一净流量，因为旧积压也在继续完成。缓存效率恢复可以增加完成率，但在完成仍慢于供给时，净积压继续长大。

已有固定客户端原件显示，两条外部队列可以先清空，活跃会话才继续结束。今天的对照新增了另一个可单独失败的条件，即缓存重新命中后，热端容量仍可能压不过到达。固定负载测量因而可同时记录持续命中、总未完成数的趋势和固定到达人群的截止交付。实测出自作者的合成重放，真实任务正确性与生产控制仍有待检验。 （已有客户端对照）

### B1 · 编辑过的旧 KV 可以在精确重算时提案

编辑上下文会改变编辑点之后的计算依赖。后缀有些 token 文字没变，旧的键和值仍编码着旧前文。对于预填与解码在不同设备上的系统，Callo 把这段失效状态当作草稿输入，在后台仍完整重算失效后缀。能否提交 token 要等精确 prompt 状态到齐，再由目标模型核验。这样，精确重算和原本空出的部分解码时间可以重叠。 （Ou 与 Lentz，2026 年 v1，§§3.2、4–5、6–8、附录 E.1–E.2）

编辑前的原样前缀照常命中。解码端按顺序将旧会话里保留的 token 映射到新位置，对键重做旋转位置编码，为新增 token 算临时状态。预填端同时对失效后缀执行精确计算，在每个至多 8,192 token 的预填分块内逐层发送。未完成时，草稿可能读到由旧状态、临时状态和已覆盖精确结果组成的上下文。在完成通知确认所有 prompt KV 到达后，解码端用精确状态对最后一个输入 token 与待核草稿做一次前向，重新计算草稿自己的 KV。从第一个拒绝点起丢弃剩余草稿，提交已接受的前缀和验证给出的下一 token。推测期写入的未验证状态也不进入共享前缀缓存。 （Callo §§4.2–4.6）

验证提交时，参考的是同一次前向给出的最高分 token。作者在独立于计时的插桩运行中固定贪心选取的并列规则，比较读到的 prompt KV 指纹、接受决策、提交 token 和回滚。在 1,928 次验证和 44,792 个提交 token 中未报告违规。批内行数或编排改变时，另一次前向的浮点计算仍可能变化，因此这项核验的参考应保留到同一次验证。 （Callo §5.5）

速度试验在两张 H200 NVL 上各放一端，使用 NVLink、vLLM 0.29 与 NIXL push。作者回放同一 SWE-agent 输入、工具间隔、到达计划与回复长度。在基准容量的 52% 负载、解码批上限 16 时，只比较双方都完成的相同请求。六组模型与历史保留设置的全请求平均时延比 vLLM/Callo 为 1.05–1.19。以 Llama-3.3-70B FP8 为例，保留最近 5/10 次完整工具输出时，未命中请求的比为 1.19/1.24，全请求为 1.14/1.19。比值包含提前传送精确 KV 和草稿两条路径。 （Callo §5.1、Table 3）

作者用 Callo-Stream 保持同样传输并关闭草稿，在三方均完成的相同请求中分辨这两部分。主配置解码批上限 16 时，草稿让 12% 与 100% 负载的全请求平均时延再降约 8% 与 10%。解码批上限为 2、达到该配置容量时，这个增量约为 3%。在主配置下，未推测请求从预填端响应到回复完成的时段平均增加约 2%（轻载）和 6%（近容量），显示普通解码也承担共享批次的代价。论文还从 52% 负载的 624 个实际推测未命中请求估计，完整方案平均节省约 0.81 秒，其中约 0.39 秒归于传输、0.42 秒归于推测，拆分依赖估计的基准 KV 到达时点。 （Callo Figs. 5–6、§5.5、附录 E.2）

库里已有直接让目标权重读旧状态的移植方式，也有事先在目标权重上生成原生状态的方法。这里的增量是把近似状态限定在提案期，再以精确计算结束待决状态。工程上的机会依赖旧 KV 仍在目标解码端、预填等待够长和解码资源有余量。固定轨迹给出了条件化的请求时延和提交检查。生产任务的完整会话成功以及跨批布局的输出一致性仍需各自证据。 （与跨权重及预填工作的关系）

### C1 · 等距音节的辨别随音位边界改变，独立标签只解释其中一部分

听者如何从连续的声学变化听出不同辅音？Liberman 等人让同一批人分别给合成音节命名与匹配声音。同样的声学步距跨过 /b/、/d/ 标注边界时，某些音对更容易分开。研究同时把标注频率变成独立预测。对相隔二步和三步的音对，实测匹配结果整体高于只凭音位标签的预测。 （Liberman 等，1957，重印 pp. 359–367）

实验的 14 个合成刺激仅在第二共振峰的起始频率上相邻差 120 Hz。标注中，听者把单音选作 /b/、/d/ 或 /g/。在 ABX 匹配中，听者先听到不同的 A 和 B，再判断 X 重复哪一个。标注记录类别选择，匹配按实际重复的刺激计分。个体 CD 对刺激 1 与 3 的匹配正确率为 55%，两者都靠 /b/ 一侧。对跨过 /b/、/d/ 边界的刺激 3 与 5，正确率为 100%。每对各有 42 次判断，物理距离都为 240 Hz。这个对照表明，仅知道第二共振峰起始频率相差多少，还无法预测这一听者的表现。 （原文 pp. 361–362、Fig. 2）

要问类别能解释多少表现，可以先算一个听者只依据随机标签作答时的正确率。设 $p_i$ 和 $q_i$ 分别为给 A、B 打第 $i$ 类标签的概率。假设三次听音独立编码，X 等可能重复任一参考音。X 的标签只与一个参考音匹配时选择该边，否则公平猜测。以公平猜测的正确率为起点，唯一匹配正确的概率贡献一半增量，唯一匹配错误的概率贡献一半减量。按这一定性规则作 AI 独立推导，匹配正确率为

$P_{\mathrm{label}}=\frac12+\frac14\sum_i (p_i-q_i)^2$ 。

标注分布相同就回到猜测水平。作为说明，A 和 B 分别以 80% 和 20% 的概率被标成 /b/，其余标为 /d/，代入预测是 68%。这一计算使用原文 p. 363 的定性规则。1958 年勘误指出该页末三式有排印问题，由于更正式未核，以上关系来自说明所列的独立假设。 （原实验与勘误位置）

原文 Figs. 5–6 对七名听者分别汇总二步、三步数据，两种间隔的预测与实测 Kendall 秩相关系数均为 0.43（原文报告 $p \lt 0.001$），且实测对预测的拟合线整体上移。一步匹配的相关较弱，约 0.14，很多预测恰为 50%。这组结果给类别模型划出了证据范围。类别分布解释一部分辨别排序。模型偏低则提示听者可能利用额外声学细节，或匹配中的线索与单音分类不同。样本里第一组五人仅保留标注稳定的三人，另四人来自熟悉合成语音的实验室。更一般的听者与刺激体系仍需对照。 （原文 pp. 365–367）

这种设计的启发是用独立任务测出标签概率，给“只记标签”的解释定量设限。它和两色同键实验有实验设计上的联系。后者改变语义与按键的映射以检查反应机制，此处则固定声学步距，用标签分布预测另一个任务。下一步可让不同母语的听者完成相同任务，或引入同维度的非语音对照，检验何种差异跟标签形成一起变化。 （音位模型推导与实验路径）

### B2 · 合成场景领先的流行病模型，在伦敦周死亡预测中落后于历史基线

滚动预测要回答未来的点预测与区间是否经得起实测。在 Rama 等人的比较中，随机机制模型在两组合成周感染上的加权区间评分更低。换成伦敦第一波周死亡后，神经代理模型的 WIS 低于随机机制模型，但两套方法都落后于只使用历史增量的基线。公开复现代码还提示，起报窗限制了逐轮拟合数据，跨整条序列选择训练种子仍可能读到更晚的信息。 （Rama 等，2026 年 v1，§§2–4 和附录指定部分）

两条流程共享按年龄分层的易感、暴露、感染、康复和死亡隔室结构。物理信息神经网络（PINN）在模拟数据上训练一次，近似连续方程的解。每一轮用当前及以前观测做参数后验采样，近期观测在 Poisson 似然中的权重更大。给定参数后，它产生确定轨迹，预测区间来自参数不确定性。另一条流程采用二项随机转移，给定参数后轨迹仍可变化，再用近似贝叶斯计算与序贯蒙特卡洛筛选能够拟合近期观测的参数与轨迹。两路的初始条件参数化也不同。作者比较的是两套流程的结果，单靠这组比较无法定位某个架构或噪声来源的作用。

基线从最新周计数开始，逐周从已观察增量及其相反数组成的经验分布里有放回抽取，累加并截到非负，每个起报点构造 10,000 条路径。这样中位数多半接近持平，区间仍反映历史波动。加权区间评分 WIS 把区间过宽、观测偏出区间的距离和中位数误差计入同一分数。实际覆盖只看观测有多少次落入区间。在同一场景内，WIS 除以该场景的基线 WIS，低于 1 表示评分优于基线。 （Rama 等，§2.6、附录 §5.5）

两组合成场景的周新感染序列含负二项观测噪声，基本再生数各为 1.5 和 2.0。真实数据是按年龄聚合的伦敦周死亡，从 2020 年 3 月 15 日首次起报，评价截止到 7 月 19 日。后者提前 1、2、3、4 周的预测分别有 18、17、16、15 个起报窗，共 66 个起报周与跨度的配对，部分对应同一目标周。下表的覆盖列记录名义 90% 区间的实际覆盖。 （论文 Tables 1、3）

| 预测对象 | PINN 归一 WIS / 覆盖 | 随机机制归一 WIS / 覆盖 | 历史基线归一 WIS / 覆盖 |
| --- | --- | --- | --- |
| 合成周感染，基本再生数 1.5 | 0.224 / 54.6% | 0.191 / 100% | 1.000 / 58.3% |
| 合成周感染，基本再生数 2.0 | 0.126 / 32.4% | 0.094 / 100% | 1.000 / 58.8% |
| 伦敦第一波周死亡 | 2.629 / 39.4% | 3.879 / 43.9% | 1.000 / 78.8% |

在伦敦对照里，PINN 比随机机制模型分数低，名义 90% 区间却只覆盖 26/66。随机机制模型覆盖 29/66，基线覆盖 52/66。这些是窗口和跨度配对的计数。重叠的预测不能当作相互独立的 66 次实验。作者另把历史窗口改为仅最近五周，同时去掉近因权重，PINN 的覆盖提高到 62.1%、归一 WIS 降到 2.206。两个设置同时变了，因此仍需单独的对照来分辨窗口和权重的作用。伦敦只有一期疫情，真实与合成目标也由感染换成了死亡，干预和行为变化未被建模。 （论文 §3.2、§4、附录 Table 8）

复现代码还给这组回测加了一道时间约束。论文结果的公开 notebook 默认加载以最佳种子命名的预计算输出。配套选种从 100 个神经网络训练种子中挑一个场景全局种子，打分依据是所有起报窗各自对当时历史的拟合 WIS。比如，3 月 22 日的计数是 3 月 15 日起报的一周预测目标，但到更晚的起报点，它已经能进入拟合评分并影响全局选种。这一判断来自固定代码路径。尚未执行 notebook 或重算预计算得分，这套选法用到了首个起报时还不可用的观测。选种规则变化对分数和排名的影响仍待测。 （公开复现范围与固定提交）

新增的验证标准是把同一目标上的历史基线和实际覆盖保留下来，同时问每个影响预测的配置何时决定。复核时可以在首个起报前锁种，或者每个起报点只用当时可见的数据重新选种，再分别比较分数与覆盖。这会直接检验公开结果能在多大程度上迁移到实时评估。 （区间与信息时点）

### A2 · Flide 的 FP8 验证固定精度，同时拒绝 FP8 与批次不变模式并用

启用 FP8 以后，通过 Flide 的验证器究竟证明了什么？固定 v0.1.16 的代码显示，量化选项会让独跑、分支和混批都使用同一个 FP8 引擎。测试关心相同权重表示经过不同执行路径时会怎样变化。若要测表示从普通权重改为 FP8 的影响，还需固定输入与执行路径后切换权重表示进行对照。 （v0.1.16 固定源码，量化与验证入口）

这一选项与批次不变模式有明确边界。引擎在构造开头拒绝同时指定 FP8 与批次不变。普通权重可以选择批次不变内核。FP8 路径按 token 缩放激活，再调用底层缩放矩阵乘法。保留这一配置差异很重要，因为此前的批次不变模式对混批比较另有 head 输出数值相等条件。新的 FP8 路径可用原首选容忍条件验收，并同时记录数值偏差。 （固定引擎入口与旧验证条件）

贡献者在纳入 v0.1.14 的改动中提供了一次可定位的运行。硬件为 RTX 5090 Laptop 24GB，模型是 OneJev1.6-0.8B，批次不变模式关闭，有 4 个请求和 6 个问题。分支对照把同一请求的多个分支一起运行，再与分别单跑比。负载对照将完整请求独跑，再与另一请求混批。下表的每个数是相同配置下，单跑基准与另一执行路径的概率坐标最大差。 （Flide PR #23，How it was tested）

| 同精度对照配置 | 同请求分支最大概率差 | 两请求一组的负载最大概率差 |
| --- | --- | --- |
| 普通权重 | 0.00736 | 0.00665 |
| FP8 | 0.0301 | 0.0387 |

在这一报告中，FP8 两项都显示 PASS，且在首选容忍判据下各为 6/6。判据允许基准前两名概率差小于 0.05 的翻转。FP8 负载对照显示输出数值相等 0/6，其日志的 “same bits” 字样对应的是数值相等检查。有限实测说明该配置下通过门槛时仍可出现不等的输出。报告未列完整逐题选择，测试也未涉及缓存恢复或任务正确率。 （报告数据、配置与判据）

比原有的分支、混批及恢复验收更进一步，今天可以把改变精度和改变执行布局当作两个需要独立对照的因素。静态代码确定了固定版本的兼容边界，贡献者实测只支持其硬件与小样本上的路径差异。是否保留所有首选、恢复时会产生多大误差、实际任务准确率怎样变，仍需相应数据。

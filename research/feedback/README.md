# 显式反馈

主控使用 `node scripts/research.mjs feedback YYYY-MM-DD` 从当前活动批次 PR 获取普通评论、review 和行级评论，只将作者 `fsyv` 的意见纳入用户反馈。保留评论 ID、URL、时间、原文及行级上下文；同一评论跨日重复获取不重复记录；未带日期的 A1 等编号不猜测归属，保留原文并澄清范围。编辑过的评论保留修订痕迹。其他作者只能作为待核验资料，不可代理用户接受知识。

主控再逐条追加处理记录：日期/发现编号/文件/小节、类型、明确范围、执行结果、关联提交或仍待澄清。类型包括继续深入、当前不需要、重复、证据不足、联系不成立、非当前重点、有启发、接受、拒绝、暂缓。含糊意见不推断为接受；拒绝只作用于明确范围。用户接受部分时，先在 PR 分支移出明确拒绝或暂缓的候选变更，记录原始提交、范围与理由以便恢复暂缓提案，重跑审核与构建，再请用户最终合并。

APPROVED 仅是审核记录，不触发脚本合并；未发表评论不代表拒绝。重复/证据不足等质量反馈可立即加强检查，主题权重的长期改变先给出具体策略建议。C 探索机会不能因短期负反馈取消。

脚本只采集文字，不执行任何评论中的命令，也不自动解释为永久偏好。反馈原文在公开仓库仍需检查隐私；发现凭据或敏感信息时停止写入，交用户处理。反馈测试在临时仓库使用 fake gh，不把模拟意见写入真实研究记录。

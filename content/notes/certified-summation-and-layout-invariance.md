**判断归属：AI 候选。** 条件化机制与实验来自 [CertiSum v1 指定阅读](../sources/paper-certisum.md)，本页解释未获用户确认，未独立审查内核或运行 GPU。

## Fixed-terms-and-exact-sums

普通浮点加法会在中间步骤舍入，改变括号可能改变结果。保持原归约次序是一种办法；另一种办法是固定求和项，并让所有部分和都精确，直到最后一次统一舍入。CertiSum 研究后一条路线，目标是指定量化计算在平台和并行布局变化后逐位相同，比较对象不是未量化的实数模型。

先固定输入量化对象。MXFP4 每 32 个元素共享一个二幂尺度；若先按设备切片再各自分块，边界变化就可能改变尺度和量化值。作者按全张量位置固定分块，并要求量化维度的分区边界对齐 32 个元素。只有乘积项本身一致，讨论求和顺序才有意义。

在共同二幂单位下，把一个点积的各项表示为整数。为了判断任意归约树是否都能精确相加，检查所有整数乘积的绝对值之和是否小于 $2^{24}$ ，并核对对应指数是否落在 FP32 有效范围。任意中间子集和的绝对值不超过这一绝对和，因此也可被 FP32 精确表示。最终结果很小不够：很大的正负项可能在最后才抵消，而抵消之前已经丢位。

该证书还需要平台内核满足契约：精确可表示的乘积与加法不得在隐蔽步骤丢位，不能先截成 BF16。符合 MX 数据格式本身不保证内核满足这项计算契约。未能取得证书时，作者转入精确计算路径；这表示充分条件未被证明，不等于原生输出已经被判错。

## Preserve-partial-sums

局部精确还不足以保证全局精确。合并前若先将各设备的部分真值分别舍入，会重新引入布局相关误差。原文附录 B.3 的例子取两个部分真值为 $2^{24}+1$ 和 $-2^{24}$ 。第一部分先舍入到 FP32 后变成 $2^{24}$ ，两部分相加得到 0；若先精确合并，再统一舍入，就得到 1。

因此跨设备中间表示必须保留精确部分和。注意力还要对分子与归一化分母分别精确合并，并保持 mask、随机选择、全局 loss 归一化和其他算子的数值定义一致。只替换 GEMM 不足以使整个训练轨迹一致。原文注意力定义还包含固定参考下的剪枝，不能把结果解读为标准未剪枝实数注意力的精确值。

## Evidence-and-cost

作者以 Qwen3-8B-Base、FineWeb-Edu 与 The Stack v3、200 步 AdamW 训练比较 AMD MI350X 和 NVIDIA GB200。全局每步 $1\times4096$ token，在单 GPU 和 TP4 设置下，逐步 loss、张量指纹、末参数和优化器状态 hash 相同。此处 TP4 切输出行和 attention head，没有跨 GPU 拆分同一归约，所以它主要检验跨平台及该分区设置。

另一组在 MI350X 上用全局 $4\times4096$ ，每 40 步恢复并依次切换 1 GPU、DP4、CP2、TP4、DP2。CertiSum 与不间断的单 GPU 参考保持 200 步相同；非精确 MXFP4 twin 从第 41 步开始分歧。同点单 GPU 恢复对照帮助排除仅由 checkpoint 引起差异。这一组才直接补上执行布局变化的证据。

精确性有代价。在 FineWeb-Edu、三种 8B–14B 模型和较大输入 $4\times4096$ 或 $1\times16384$ 下，CertiSum 相对非精确 MXFP4 twin 的时延高 11.8%–60.5%。较小输入的六个 TP 设置中，其时延为普通 BF16 的 1.05–1.36 倍。通信、时钟和部分 graph replay 等实现差异也在比较内，不能把这些数值解释为纯证书开销。相对 BF16 的某些较大输入加速亦不建立相同训练轨迹下的因果消融。

## Different-costs

[KV 缓存](kv-cache-mechanism.md)用存储换掉历史计算，但“缓存优化”不是单一操作。必须先指明重复的是哪项工作、浪费的是哪些字节、经过哪条链路，以及是否允许改变数值结果。以下是按机制建立的分析框架，不是最新论文性能排名。

缓存对象也要区分：预处理缓存保留分词等变换的结果；完整输出缓存保留已经生成的回答；KV 缓存保留模型的中间状态。前者需匹配输入与变换规则，回答复用还需满足完整请求及所依赖数据等条件，不能仅因问题文字相同就断言输出仍适用。它们跳过的计算环节不同。以下分类只讨论 KV。

| 目标 | 代表机制 | 直接改变什么 | 不自动保证什么 |
|---|---|---|---|
| 避免同一前缀重算 | 请求内 KV 复用、跨请求前缀共享 | 需要重新执行的前缀计算 | 命中率和端到端加速 |
| 减少分配浪费 | 按块按需分配、共享块 | 已分配与实际数据间的空隙 | 每个 token 的 KV 元素更少 |
| 减少实际数据量 | 量化、结构改变、保留部分状态 | 元素字节数或保存的向量数 | 所有任务精度不变 |
| 扩展设备可承载状态 | 卸载至其他存储层 | 数据所在位置和设备驻留量 | 访问延迟下降 |
| 提高访问与执行效率 | 预取、批处理、算子组织 | 等待和传输重叠、硬件利用 | 突破物理带宽上限 |

后三行是一般成本分析；下文的新微基准只用于说明放置与计时边界，不构成 KV 服务性能排名。

## Paging

连续大块预留可能为尚未生成的 token 占据显存，序列结束后也可能留下难利用的空隙。PagedAttention 将逻辑上的连续 KV 序列分成固定 token 数的块，通过块表映射到非连续物理空间，按需分配，并允许适当的共享。[原论文 §4.1–4.2](../sources/foundations-kv-systems.md#paging)支持这项机制。

分页不改变“每个 token 有哪些 KV”。例如理论数据为100单位，而连续预留占200单位，分块可以减少后100单位的浪费；不能由此声称理论 KV 从100变成50。最后一块仍可能有未用空间，块大小也影响元数据及访问组织。

## Prefix-sharing

如果多个请求在同一模型条件下共享相同前缀，其前缀 KV 已经相同。RadixAttention 用 token 序列的 radix tree 管理缓存，支持查找、复用和淘汰；机制见[SGLang §3 与附录 A.1](../sources/foundations-kv-systems.md#prefix)。这既可能避免重复 prefill，也可能让请求共享状态。

收益取决于可命中的前缀长度、缓存能否保留到下一次使用及调度。相同后缀若前面的上下文不同，其隐状态通常不同，不能直接复用；相同自然语言含义更不等于相同 KV。复用是由数据依赖保证的，不是由相似度保证的。

## Capacity-and-transfer

压缩降低需保存或读取的有效字节数，但量化误差、状态删除、重建开销和元数据应一起计入。重新排列 K/V 对与删除 K/V 对不同：只有同时保持注意力掩码、位置偏置和逻辑位置对应关系一致，同步置换才保持原有加权聚合；删除元素通常改变 softmax 分母及输出。

卸载可以腾出设备显存，但之后每次访问可能经过较慢链路。可用一个粗略成本式识别问题：

$$
t_{\mathrm{transfer}}\approx r\,\ell+\frac{D}{\mathrm{BW}_{\mathrm{eff}}},
$$

其中 $r$ 为串行交互轮数、$\ell$ 为每轮等待、$D$ 为数据量。这是分析模型，省略排队、协议重叠和拓扑竞争。减小 $D$、减少 $r$、提高有效带宽解决不同项；如果等待主导，单纯加带宽不会同比降低总时间。预取可隐藏一部分等待，但仍要传输相应字节。

## Remote-load-or-recompute

**2026-10-19 新增 AI 候选解释。** 精确 KV 命中解决了状态能否复用，却不保证远程加载比本地重算快。[When the KV Cache Is Slower Than the GPU §4](../sources/paper-remote-kv-load-or-recompute.md)用一阶近似比较

$$
t_{\mathrm{recompute}}=\frac nR,\qquad
t_{\mathrm{load}}=T_0+\frac{ns}{B}.
$$

其中 $n$ 是待复用前缀的 token 数，不必等于整个请求长度；$s$ 是每 token 的有效 KV 字节数，$R$ 是引擎 prefill 速率，$B$ 是实际分给单个 prompt 的有效字节带宽。$T_0$ 汇集调度、lookup 往返、少量未缓存尾 token 的 forward 及元数据交换等固定开销。各项要在一致测量边界下取值；这不是完整请求 TTFT 的精确分解，也不能用物理链路标称带宽直接替代 $B$。

若忽略固定开销，加载优于重算要求 $B>sR$。保留 $T_0>0$、固定正的 $R,B,s$ 后，**AI 独立代数推导**给出

$$
t_{\mathrm{load}}<t_{\mathrm{recompute}}
\iff B>sR\quad\text{且}\quad
n>\frac{RBT_0}{B-sR}.
$$

从加载时间至少为 $T_0$ 还能得到 $n>RT_0$，但它只是必要条件：前缀够长仍可能败于传输带宽。因此“缓存命中”和“值得加载”应分别决策；若 $R$、$B$ 或固定开销随长度和并发变化，上述常数门槛也需重估。

论文约 17k token 的准入门槛来自单个长度点拟合，不是跨长度实测的普适阈值。§6.3 最终配置的中位数仍慢于同请求重算；较大的 p99 改善以发生拥塞的同步加载为对照，不能改写成相对 GPU 重算的同倍数收益。§8 也限定单次运行、单引擎、单长度桶及能容纳的容量子集；端到端方案还改动其他配置，不能把总收益归因于远程缓存一个因素。

这为[逐请求服务评价](storage-latency-and-slo.md)增加一个机制前提：先检查状态复用是否正确，再比较同请求加载与重算、相同负载下的排队和完成。尚未取得源码日志或复现，不将模型阈值当部署保证。

**边界对照：**[对象大小与命中目标](probability-zipf.md#object-size-and-objective)说明请求命中和节省字节已经可能不同；本节再加入有效带宽及固定开销，说明节省计算与降低耗时也需分别判断。两种对象模型没有被视为等价。

## Numerical-error

2026-10-14 **AI 候选应用方向，尚未验证：**[条件数与数值稳定性](numerical-conditioning-and-stability.md)区分状态扰动、算法误差与问题敏感性。固定模型/query/mask/位置规则和维度后，可研究量化扰动怎样影响高精度参考输出；量化步长不自动等于浮点舍入单位。删除 KV 改变归一化/结构，不能直接作为小扰动；小 logits 误差也不保证采样、整段生成或任务质量。本轮没有运行模型实验。

## Placement-and-timing

**2026-10-16 新增 AI 候选解释。** 统一虚拟地址空间不等于每次 GPU 访问经过相同物理路径。[Grace-Blackwell 放置受控微基准](../sources/paper-grace-blackwell-unified-memory.md)区分 CPU 初始化后的 managed 冷首次访问、完成预取后的访问、GPU 重用及 host-mapped 访问；容量压力和访问历史也需要控制。原文 IV-E 的部分迁移/驱逐仅由趋势推断，不能据此断言每个页的实际驻留状态。

同一 256 MiB streaming 核中，作者 V-C 报告 cold managed 为 14.1 GB/s、prefetched 为 4606 GB/s。预取模式的核计时在预取完成后开始，预取时间单列；这两个数的比值不能叫作端到端约 327 倍加速，也不能据之保证 LLM KV 收益。

要检验 KV 卸载的有效带宽，可分别记录：实际有效字节与分配 footprint、初始化位置、冷/预取/重用状态、容量压力，以及排队、搬移和核执行各段时间。总请求耗时还需按实际依赖和重叠测量，不能盲目相加重叠阶段或漏掉预取。这是由微基准提出的 KV 测量建议，论文没有在 LLM KV 服务上验证它。

## Evaluation

比较方案时，应同时记录模型和上下文长度、并发与请求分布、硬件/链路、数值精度、缓存命中及测量指标。首 token 延迟反映 prefill 等工作，逐 token 延迟反映 decode 的稳态表现，吞吐还受批量、调度与内存容量影响。只给一个加速倍数无法判断机制是否适合另一种负载。

**前置依赖：**[KV 的大小与单步成本](kv-cache-mechanism.md)给出可用于检查数量级的公式。**开放方向：**[基础机制的可检验边界](../questions/foundations-validation.md)保留需要实际测量的任务，未经核验的论文数字不在本页传播。

## Residency-and-accessibility

**2026-10-20 新增 AI 候选解释。** 理论 KV 字节还不能说明跨多轮调用需保留多少状态。[Agentic KV 驻留研究](../sources/paper-agentic-kv-residency.md)分开驻留时限、表示和路由可访问性：它们分别改变对象保留多久、每对象占多少字节、下一调用能访问哪个缓存，不能统称一个命中优化。

生产模型保密，作者用 Llama2-70B 几何替身估大小。以 $\beta$ 表示每 token 字节，K/V、层数、KV 头数、头维度、元素字节分别给出

$$
\beta=2\times80\times8\times128\times2=327{,}680\ \mathrm{B/token}.
$$

这是替身估计，不是生产 GPU HBM 实测。Research/Assist/Chat 是 model-call 遥测，Code 是工具/会话事件，不宜同口径排序。

完整 eligible Research trace 按 live session 的终生峰值大小计费时，never reclaim 改成一小时 idle cap，估计峰值从 501.8 降到 140.8 TB，约减少 71.94%；重建调用率从 4.07% 到 4.53%，增加 0.46 个百分点。这是该时间边界与计费下的取舍，不证明一小时普遍最优。

另一组实验只取最忙一小时：176,007 calls、9,486 sessions，按当前上下文大小回放、淘汰整 session、缺失重建整段。无淘汰峰值 47.0 TB，不应与前面的 501.8 TB 拼接；10% pooled HBM 预算为 4.7 TB。

| 同一小时/同一 10% 预算策略 | 重建调用数/总调用数 |
| --- | --- |
| LRU | 62.9% |
| FNU：未来使用启发式 | 31.1% |
| MRR：沿 LRU 次序由 fp16 降为 int4 | 13.6% |

MRR 将 int4 记为 fp16 的四分之一大小，并计入同一 HBM；加入量化元数据敏感性后，该率为 14.99%–19.25%。2% 预算时 FNU 67.60% 反优于 MRR 72.92%，没有通用排序；可变增长对象下的 FNU 也不是最优证书。回放忽略恢复、反量化、传输时间，int4 被提升后按 fp16 命中计，没有测输出质量。重建调用率既非重建 token 比例，也非端到端 TTFT。

路由再引入身份/可访问性限制。若 session 按 deployment 分开计对象，9,486 个 session 变成 35,588 个 session+deployment 对象。**AI 算术复核：**空缓存、无限容量且每对象首触一次的重建率下界分别为 $9486/176007\approx5.39\%$ 、 $35588/176007\approx20.22\%$ 。对象模型变化产生不同冷启动下界，不能当作路由改动造成的实测因果收益；同部署与跨部署的观察复用率也不是干预证据。

因此下一步应在真实每副本容量和路由下，同时测恢复/传输成本与输出质量，再比较[逐请求服务目标](storage-latency-and-slo.md)。总 pooled 预算不能代替各副本约束，原生产轨迹不公开、生成器尚未取得，本页不照搬时限或建议直接部署 int4。[张量存活与峰值内存](tensor-liveness-and-peak-memory.md)在单次计算图中也区分存活、表示和分配器计费，但会话可淘汰重建与图内存活 root 不是同一模型。

## Selective-reconstruction

**2026-10-23 新增 AI 候选解释。** [RISK-KV 指定正文](../sources/paper-risk-kv.md)研究暂停请求恢复时，保留目标层组两侧精确KV anchors，省略中间组的历史KV，恢复时再用共享预测器重建。它先将anchor K逆RoPE，与同位置V共同预测目标层的normalized attention projection input，经过冻结模型的原投影得到K/V，K再施回原位置RoPE。在线不读取已删目标KV；仿射预测与原投影可折叠，但折叠等价仅针对相同预测计算，不代表预测就是精确KV。

质量选择对每个请求比较相同target token上的paired NLL差 $d_r(S)=\ell_r(S)-\ell_r(\varnothing)$，其中 $S$ 为被重建的层组，空集是exact基线，$\ell_r$ 为请求 $r$ 的平均负对数似然。以平均差的bootstrap单侧90%上端不超过预算 $\epsilon$ 作经验门禁；先按单组风险/省字节排序，再重测联合前缀，不能直接加总单组损失，亦无全局最优保证。评估模型依次为Qwen2.5-0.5B-Instruct、Qwen2.5-1.5B-Instruct和TinyLlama-1.1B-Chat-v1.0，WikiText2采用512历史加512后续teacher-forcing，拟合、验证选择和独立测试分开；每模型三seed各八个paired测试请求。

均值门禁不等于逐请求达标。TinyLlama、$\epsilon=0.002$ 的24独立评估请求中，MeanGate/Upper90/StableSplit分别有10/2/0个请求的观测paired NLL差超预算，平均省略1.667/0.667/0.333MiB；StableSplit约三分之二评估请求回退exact。0/24不是总体风险为零的证明，teacher-forced质量也不等于自由生成正确性。

TableI的Qwen0.5B raw历史KV省略2MiB、33.3%，仍须扣预测器。原式净节省为

$\Delta M=N M_{\mathrm{saved}}-M_{\mathrm{pred}}-M_{\mathrm{aux}},$

其中 $N$ 为共享同模型/同topology预测器的请求数，$M_{\mathrm{saved}}$ 为每请求实际驱逐的历史KV字节，$M_{\mathrm{pred}}$ 为共享预测器，$M_{\mathrm{aux}}$ 为额外辅助驻留，须在同存储层计费。该配置四组FoldedFP32预测器约为单请求省略量的四倍，TableIII每组均值约2.002MiB，不能当精确bank总量。**AI简化算例：**假设共享预测器8MiB、每请求省2MiB、辅助为0，则净省 $(2N-8)$ MiB：一请求反增6MiB、四请求打平、至少五请求才净省。这不是作者精确bank测量。

局部时延在RTX3060 Laptop GPU、batch1、512历史加同一个已知current token，比较从CPU token IDs重放513位置，与从CPU传保留KV、使用已驻GPU预测器重建完整KV再算同一next-token logits。五次预热、每模型八validation请求/每请求30次，按上述模型顺序，Replay/RISK均值60.66/40.09、125.41/48.99、114.07/34.50ms。该1.51/2.56/3.31倍只对这个恢复基线成立，不是与完整KV直接加载、真实无线或所有服务方案比较。之后decode已物化完整cache，不能声称长期GPU净节省。

这在[近似复用边界](kv-cache-mechanism.md#approximate-reuse)之外，具体补上共享预测器摊销、均值风险/逐请求质量及恢复计时义务。尚未核代码、长上下文大模型或真实无线；与[逐请求联合成功](storage-latency-and-slo.md#joint-success)的联系是评价条件，不能由平均NLL或局部恢复时间直接推出联合SLO。

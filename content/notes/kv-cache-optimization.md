## Different-costs

[KV 缓存](kv-cache-mechanism.md)用存储换掉历史计算，但“缓存优化”不是单一操作。必须先指明重复的是哪项工作、浪费的是哪些字节、经过哪条链路，以及是否允许改变数值结果。以下是按机制建立的分析框架，不是最新论文性能排名。

缓存对象也要区分：预处理缓存保留分词等变换的结果；完整输出缓存保留已经生成的回答；KV 缓存保留模型的中间状态。前者需匹配输入与变换规则，回答复用还需满足完整请求及所依赖数据等条件，不能仅因问题文字相同就断言输出仍适用。它们跳过的计算环节不同。以下分类只讨论 KV。

| 目标 | 代表机制 | 直接改变什么 | 不自动保证什么 |
|---|---|---|---|
| 避免同一前缀重算 | 请求内 KV 复用、跨请求前缀共享 | 需要重新执行的前缀计算 | 命中率和端到端加速 |
| 减少分配浪费 | 按块按需分配、共享块 | 已分配与实际数据间的空隙 | 每个 token 的 KV 元素更少 |
| 减少实际数据量 | 量化、结构改变、保留部分状态 | 元素字节数或保存的向量数 | 所有任务精度不变 |
| 扩展设备可承载状态 | 卸载至其他存储层 | 数据所在位置和设备驻留量 | 访问延迟下降 |
| 提高访问与执行效率 | 预取、批处理、算子组织 | 等待和传输重叠、硬件利用 | 突破物理带宽上限 |

后三行是一般成本分析；下文的新微基准只用于说明放置与计时边界，不构成 KV 服务性能排名。

## Paging

连续大块预留可能为尚未生成的 token 占据显存，序列结束后也可能留下难利用的空隙。PagedAttention 将逻辑上的连续 KV 序列分成固定 token 数的块，通过块表映射到非连续物理空间，按需分配，并允许适当的共享。[原论文 §4.1–4.2](../sources/foundations-kv-systems.md#paging)支持这项机制。

分页不改变“每个 token 有哪些 KV”。例如理论数据为100单位，而连续预留占200单位，分块可以减少后100单位的浪费；不能由此声称理论 KV 从100变成50。最后一块仍可能有未用空间，块大小也影响元数据及访问组织。

## Prefix-sharing

如果多个请求在同一模型条件下共享相同前缀，其前缀 KV 已经相同。RadixAttention 用 token 序列的 radix tree 管理缓存，支持查找、复用和淘汰；机制见[SGLang §3 与附录 A.1](../sources/foundations-kv-systems.md#prefix)。这既可能避免重复 prefill，也可能让请求共享状态。

收益取决于可命中的前缀长度、缓存能否保留到下一次使用及调度。相同后缀若前面的上下文不同，其隐状态通常不同，不能直接复用；相同自然语言含义更不等于相同 KV。复用是由数据依赖保证的，不是由相似度保证的。

## Session-lifecycle-and-sharing

**2026-11-11 AI 候选。** 判断前缀块何时可以回收，需要知道哪些执行会再次读它。工具调用期间，模型请求已经结束，整个会话仍可能回来读取历史。若确知一个块只服务该会话，真实结束事件给出回收边界。一个跨会话复现的公共前缀可能在当前所有读者都离开之后，再被尚未到来的会话请求。即使结束事件完全准确，它也无法回答这一块未来还有没有其他读者。

[Chen 等 v1 的轨迹对照](../sources/paper-storage-view-kv-cache.md)用不限容量、无淘汰时的块读计算潜在命中率。RAGBench 的 71% 来自不同单轮会话之间，WildChat 的 74% 则主要来自多轮会话自己的历史。相近的命中比例由不同复用范围生成，无法单独决定持有期限。作者按历史逐步标记块的第二次读取。在四种指定工作负载中，按请求次数标记 2600–12600 GiB，其中 0.1%–16% 后来被另一个会话读取。改为观察到第二个不同会话后才标记，标记量为 18–1100 GiB，其中 41%–99% 后来又被另一个会话读取。每个百分比以该规则标记的字节量为分母，观察窗口内还未出现第二个会话的块不会被后者选中。结果衡量已标记状态的后续复用比例，无法据此估计全部将复用块的召回率、有限容量命中率或吞吐。

一个说明性算例里，两块都被同一会话反复读了十次。会话结束前，这两块有相同的次数、会话身份和完成时点。假设一个块此后无人访问，另一个块被新会话第一次复用，回收时可见的三种信号无法区分两者。第二个会话 ID 能确认已发生的跨会话共享，未知块仍需保留策略或另有预测依据。工作负载 ID 则可界定从哪些历史数据估计空闲期限，各类信号对应不同的决策缺口。

[客户端恢复控制](session-cache-pressure-and-metastability.md#client-gate-and-session-completion)用完整会话完成衡量固定窗口服务结果。那是终点验收的口径。这里的完成信号帮助判断单会话缓存的寿命，两者都需要区分单次调用结束与整个会话结束。

## Capacity-and-transfer

压缩降低需保存或读取的有效字节数，但量化误差、状态删除、重建开销和元数据应一起计入。重新排列 K/V 对与删除 K/V 对不同：只有同时保持注意力掩码、位置偏置和逻辑位置对应关系一致，同步置换才保持原有加权聚合；删除元素通常改变 softmax 分母及输出。

卸载可以腾出设备显存，但之后每次访问可能经过较慢链路。可用一个粗略成本式识别问题：

$$
t_{\mathrm{transfer}}\approx r\,\ell+\frac{D}{\mathrm{BW}_{\mathrm{eff}}},
$$

其中 $r$ 为串行交互轮数、$\ell$ 为每轮等待、$D$ 为数据量。这是分析模型，省略排队、协议重叠和拓扑竞争。减小 $D$、减少 $r$、提高有效带宽解决不同项；如果等待主导，单纯加带宽不会同比降低总时间。预取可隐藏一部分等待，但仍要传输相应字节。

## Four-bit-kernels-and-request-cost

**2026-11-25 AI 候选解释。** 四位 KV 读的字节更少，软件解码却要多发出指令。在没有 FP4 硬件的 Hopper 上，省下的带宽可能被解包、缩放和等待吃掉。[Zhang 的 H200 指定对照](../sources/paper-hopper-four-bit-kv-decoding.md)把这条链从注意力内核推进到整步解码和完整请求，说明容量收益与用户总等待仍可方向相反。

首先核查计算能否跟上访存。论文 §3 按 H200 的 132 个 SM、每 SM 四个调度器、每条 warp 指令 32 个 lane 与 1.98 GHz 计算，每秒约能发出 33 万亿条线程指令；除以 4.8 TB/s 标称带宽，约为每字节七条。NVFP4 每 128 个值使用 72 字节，满带宽对应每值约 3.9 条指令。这是作者用规格构造的预算估算，不是每种输入都能达到的硬上限证明。表 2 在批量 32、长度 16K 的同形状比较中，FlashInfer NVFP4 每值 8.3 条指令、达到 19% 带宽，UltraQuant 为 22.5 条、8%。去掉 spinwait 的 BitDecoding 降至 3.6 条，仍只有 25% 带宽；减少指令后，加载与计算之间的串行等待仍会限制吞吐。

新内核同时改变执行重叠和表示布局。一个 TMA producer 用双缓冲搬入每段 256 个 token，两组 compute warpgroups 交错解码与矩阵运算，再合并 softmax。对小 query 组，转置 K/V 的矩阵角色，使解码值从寄存器进入 A 操作数，减少共享内存往返和填充。缓存写入时也排列好 codes 与 scale，使读取后的片段更接近矩阵指令需要的顺序。这些措施组合起来减少等待，不能把结果归因于位宽一个因素。

要比较收益，先固定 H200 SXM 141 GB、Llama-3.1-8B 的形状：8 个 KV head、分组比 4、head 维度 128。表 5 在同一运行中用 CUDA graph replay，逐形状为各内核取最佳 page/split 配置；批量 32、长度 16K 时，新 NVFP4 内核为 0.1876 ms，XQA FP8 为 0.2547 ms，FA4 FP8 为 0.2551 ms，约快 1.36 倍。表 7 改测 vLLM 0.33.0 的完整解码一步，同形状下 XQA FP8 为 12.66 ms，原 vLLM NVFP4 为 26.36 ms，新路径为 10.94 ms；相对 FP8 的收益缩为约 1.16 倍。两表的测量对象不同，内核倍数不能直接作为模型整步倍数。

整步结果还依赖质量配置：新路径执行 K 均值移除和 Hadamard 旋转，前四个 token 与第零层使用 BF16，显存利用率设为 0.90、页大小为 64 token。在这一混合配置下，可容纳 2,867,200 个 token，FP8 为 1,761,600 个，约相差 1.63 倍。这不是全部状态都压到四位的容量比，也不是输出与 BF16 逐位一致的保证。

更大的容量能减少等待 KV 槽位，却未必缩短一次请求的总时长。同节随后在批量 64、长度 32K 的端到端对照中，FP8 容不下全部 64 条序列，新路径可以容纳。对同一任务、固定生成 256 个 token 的对照为：

| 口径 | 新四位混合路径 | FP8 / XQA |
| --- | ---: | ---: |
| 包含等待 KV 槽位的 decode TPOT | 38.7 ms | 52.2 ms |
| 约 210 万 prompt token 的 prefill | 77.0 s | 71.7 s |
| 完整任务总时长 | 86.8 s | 85.0 s |

较短 decode TPOT 没有抵消更慢的 prefill，因而总时长轻微反转。这不是四位缓存普遍更慢的证据，而是在明确输入输出比例下，容量、解码与预填必须共同计入的实测例子。论文另测开放到达负载，API 处理也可转为瓶颈；少数配置或种子达标不能写成无条件可持续的请求率。

质量与性能还须分开验收。原文 §8–9 的有限样本没有检出显著准确率差异，部分区间约宽至正负 2.5–3 个百分点，80% 检验功效下可检测差异约为 3.3–4.6 个百分点；这不证明无损或等价。当前范围还限单 GPU、特定维度和分组，缺少真实轨迹、共享前缀和张量并行的同条件测试。本库未审源码或运行 GPU；[固定数值对象的验证](numerical-conditioning-and-stability.md#fixed-attention-and-input-rounding)提供检查输入表示与机器输出的前置方法，不能由随机输入验证替代真实模型切片。

相较本页原有字节与传输模型，这项证据增加了两层判断：减少字节后，要确认指令预算与等待能否兑现带宽；兑现内核收益后，还要检查质量配置、容量调度及完整请求是否获益。[逐请求时延与 SLO](storage-latency-and-slo.md)定义最终评价对象，而不是用单一压缩比替代它。

## Remote-load-or-recompute

**2026-10-19 新增 AI 候选解释。** 精确 KV 命中解决了状态能否复用，却不保证远程加载比本地重算快。[When the KV Cache Is Slower Than the GPU §4](../sources/paper-remote-kv-load-or-recompute.md)用一阶近似比较

$$
t_{\mathrm{recompute}}=\frac nR,\qquad
t_{\mathrm{load}}=T_0+\frac{ns}{B}.
$$

其中 $n$ 是待复用前缀的 token 数，不必等于整个请求长度；$s$ 是每 token 的有效 KV 字节数，$R$ 是引擎 prefill 速率，$B$ 是实际分给单个 prompt 的有效字节带宽。$T_0$ 汇集调度、lookup 往返、少量未缓存尾 token 的 forward 及元数据交换等固定开销。各项要在一致测量边界下取值；这不是完整请求 TTFT 的精确分解，也不能用物理链路标称带宽直接替代 $B$。

若忽略固定开销，加载优于重算要求 $B>sR$。保留 $T_0>0$、固定正的 $R,B,s$ 后，**AI 独立代数推导**给出

$$
t_{\mathrm{load}}<t_{\mathrm{recompute}}
\iff B>sR\quad\text{且}\quad
n>\frac{RBT_0}{B-sR}.
$$

从加载时间至少为 $T_0$ 还能得到 $n>RT_0$，但它只是必要条件：前缀够长仍可能败于传输带宽。因此“缓存命中”和“值得加载”应分别决策；若 $R$、$B$ 或固定开销随长度和并发变化，上述常数门槛也需重估。

论文约 17k token 的准入门槛来自单个长度点拟合，不是跨长度实测的普适阈值。§6.3 最终配置的中位数仍慢于同请求重算；较大的 p99 改善以发生拥塞的同步加载为对照，不能改写成相对 GPU 重算的同倍数收益。§8 也限定单次运行、单引擎、单长度桶及能容纳的容量子集；端到端方案还改动其他配置，不能把总收益归因于远程缓存一个因素。

这为[逐请求服务评价](storage-latency-and-slo.md)增加一个机制前提：先检查状态复用是否正确，再比较同请求加载与重算、相同负载下的排队和完成。尚未取得源码日志或复现，不将模型阈值当部署保证。

**边界对照：**[对象大小与命中目标](probability-zipf.md#object-size-and-objective)说明请求命中和节省字节已经可能不同；本节再加入有效带宽及固定开销，说明节省计算与降低耗时也需分别判断。两种对象模型没有被视为等价。

## Numerical-error

2026-10-14 **AI 候选应用方向，尚未验证：**[条件数与数值稳定性](numerical-conditioning-and-stability.md)区分状态扰动、算法误差与问题敏感性。固定模型/query/mask/位置规则和维度后，可研究量化扰动怎样影响高精度参考输出；量化步长不自动等于浮点舍入单位。删除 KV 改变归一化/结构，不能直接作为小扰动；小 logits 误差也不保证采样、整段生成或任务质量。本轮没有运行模型实验。

## Placement-and-timing

**2026-10-16 新增 AI 候选解释。** 统一虚拟地址空间不等于每次 GPU 访问经过相同物理路径。[Grace-Blackwell 放置受控微基准](../sources/paper-grace-blackwell-unified-memory.md)区分 CPU 初始化后的 managed 冷首次访问、完成预取后的访问、GPU 重用及 host-mapped 访问；容量压力和访问历史也需要控制。原文 IV-E 的部分迁移/驱逐仅由趋势推断，不能据此断言每个页的实际驻留状态。

同一 256 MiB streaming 核中，作者 V-C 报告 cold managed 为 14.1 GB/s、prefetched 为 4606 GB/s。预取模式的核计时在预取完成后开始，预取时间单列；这两个数的比值不能叫作端到端约 327 倍加速，也不能据之保证 LLM KV 收益。

要检验 KV 卸载的有效带宽，可分别记录：实际有效字节与分配 footprint、初始化位置、冷/预取/重用状态、容量压力，以及排队、搬移和核执行各段时间。总请求耗时还需按实际依赖和重叠测量，不能盲目相加重叠阶段或漏掉预取。这是由微基准提出的 KV 测量建议，论文没有在 LLM KV 服务上验证它。

## Attention-gates-and-eviction

**2026-11-09 AI 候选解释。** KV 淘汰要预测删除历史条目后，剩余条目还能否支持生成。普通注意力会重新分配删掉条目原来获得的权重。因此训练连续保留分数时，应检查训练的门控是否实际改变了归一化后的分布。[Gu 等 v1 §2–3](../sources/paper-kv-eviction-gating.md)提供了门控构造与消融。

固定一行查询和一个注意力头，令 $a_j$ 为原来分给可见键 $j$ 的注意力权重，$g_j$ 为其非负保留乘数。只要至少一个有正权重的条目保留，应用门控后的权重为

$$
a'_j=\frac{a_j g_j}{\sum_k a_k g_k}.
$$

分母对同一查询的可见键 $k$ 求和。硬掩码的乘数取零或一，此式正好是在保留集合上重新计算普通注意力。若在 softmax 后仅乘上 value 贡献，分母没有变化，被移除的注意力质量也没有分给其余条目。正乘数在 softmax 内等价于给相应 logit 加上 $\log g_j$。当一行的乘数全为同一正数时，它在分子和分母中抵消。训练因此允许连续门控保留稠密分布，却不能用这个常数评分选择离散 top-k。恒等式说明连续训练的解空间，不能据此推得语言模型交叉熵总以该解为最优。

原文保留若干起始项和近期窗口，把这些乘数固定为一，再让可淘汰集合 $E$ 的乘数共享总量 $\beta$。在保护集合非空、可见 logit 有限且 $0<\beta<|E|$ 时，若整行权重仍等于稠密权重，正权重约分会要求所有乘数都等于同一个归一化常数。任一受保护项把这个常数固定为一，于是 $E$ 内乘数之和应为 $|E|$，与预算矛盾。这只排除整行原样保留。可淘汰项仍可得到同样的评分，value 的组合也可能恰好相同。$\beta$ 是训练乘数之和，实际保存槽数是另一个推理约束。

冻结骨干后，原文用全 KV 骨干的下一词元分布作蒸馏目标，让优化关注淘汰前后的预测差异。论文 §3.1 的 Qwen3-0.6B 对照在 RULER 8K 使用 2048/8192 槽，各分支训练 100 步。直接 LM 损失、无保护且均分各头槽数时，平均分为 4.33。加入保护与训练预算构造后为 44.86，改用 KL 后为 58.86，再按各头在最终 prefill 查询可保留的注意力质量分配槽数后为 67.60。未淘汰骨干为 70.01。第一步同时改变训练和推理的保护构造，分差对应这一组合。

头内评分回答给定槽数时留哪些键。各头对其所有评分加同一个常数时，头内 softmax 和排序均不变，跨头比较原始分数因此缺少固定标尺。作者把实际槽数分给达到共享累计注意力质量目标所需的各头保留集合，并调整目标与整数余量以满足总预算。训练门控能否改变权重、头内选择是否有效和头间预算怎么给，是三个可分别检查的问题。此处的输入是保留集合，和[上下文兼容修复](kv-cache-mechanism.md#contextual-compatibility)处理的复用状态失配不同。相同保留比下的服务代价仍取决于实现、请求和质量口径。

## Residency-and-accessibility

**2026-10-20 新增 AI 候选解释。** 理论 KV 字节还不能说明跨多轮调用需保留多少状态。[Agentic KV 驻留研究](../sources/paper-agentic-kv-residency.md)分开驻留时限、表示和路由可访问性：它们分别改变对象保留多久、每对象占多少字节、下一调用能访问哪个缓存，不能统称一个命中优化。

生产模型保密，作者用 Llama2-70B 几何替身估大小。以 $\beta$ 表示每 token 字节，K/V、层数、KV 头数、头维度、元素字节分别给出

$$
\beta=2\times80\times8\times128\times2=327{,}680\ \mathrm{B/token}.
$$

这是替身估计，不是生产 GPU HBM 实测。Research/Assist/Chat 是 model-call 遥测，Code 是工具/会话事件，不宜同口径排序。

完整 eligible Research trace 按 live session 的终生峰值大小计费时，never reclaim 改成一小时 idle cap，估计峰值从 501.8 降到 140.8 TB，约减少 71.94%；重建调用率从 4.07% 到 4.53%，增加 0.46 个百分点。这是该时间边界与计费下的取舍，不证明一小时普遍最优。

另一组实验只取最忙一小时：176,007 calls、9,486 sessions，按当前上下文大小回放、淘汰整 session、缺失重建整段。无淘汰峰值 47.0 TB，不应与前面的 501.8 TB 拼接；10% pooled HBM 预算为 4.7 TB。

| 同一小时/同一 10% 预算策略 | 重建调用数/总调用数 |
| --- | --- |
| LRU | 62.9% |
| FNU：未来使用启发式 | 31.1% |
| MRR：沿 LRU 次序由 fp16 降为 int4 | 13.6% |

MRR 将 int4 记为 fp16 的四分之一大小，并计入同一 HBM；加入量化元数据敏感性后，该率为 14.99%–19.25%。2% 预算时 FNU 67.60% 反优于 MRR 72.92%，没有通用排序；可变增长对象下的 FNU 也不是最优证书。回放忽略恢复、反量化、传输时间，int4 被提升后按 fp16 命中计，没有测输出质量。重建调用率既非重建 token 比例，也非端到端 TTFT。

路由再引入身份/可访问性限制。若 session 按 deployment 分开计对象，9,486 个 session 变成 35,588 个 session+deployment 对象。**AI 算术复核：**空缓存、无限容量且每对象首触一次的重建率下界分别为 $9486/176007\approx5.39\%$ 、 $35588/176007\approx20.22\%$ 。对象模型变化产生不同冷启动下界，不能当作路由改动造成的实测因果收益；同部署与跨部署的观察复用率也不是干预证据。

因此下一步应在真实每副本容量和路由下，同时测恢复/传输成本与输出质量，再比较[逐请求服务目标](storage-latency-and-slo.md)。总 pooled 预算不能代替各副本约束，原生产轨迹不公开、生成器尚未取得，本页不照搬时限或建议直接部署 int4。[张量存活与峰值内存](tensor-liveness-and-peak-memory.md)在单次计算图中也区分存活、表示和分配器计费，但会话可淘汰重建与图内存活 root 不是同一模型。

## Selective-reconstruction

**2026-10-23 新增 AI 候选解释。** [RISK-KV 指定正文](../sources/paper-risk-kv.md)研究暂停请求恢复时，保留目标层组两侧精确KV anchors，省略中间组的历史KV，恢复时再用共享预测器重建。它先将anchor K逆RoPE，与同位置V共同预测目标层的normalized attention projection input，经过冻结模型的原投影得到K/V，K再施回原位置RoPE。在线不读取已删目标KV；仿射预测与原投影可折叠，但折叠等价仅针对相同预测计算，不代表预测就是精确KV。

质量选择对每个请求比较相同target token上的paired NLL差 $d_r(S)=\ell_r(S)-\ell_r(\varnothing)$，其中 $S$ 为被重建的层组，空集是exact基线，$\ell_r$ 为请求 $r$ 的平均负对数似然。以平均差的bootstrap单侧90%上端不超过预算 $\epsilon$ 作经验门禁；先按单组风险/省字节排序，再重测联合前缀，不能直接加总单组损失，亦无全局最优保证。评估模型依次为Qwen2.5-0.5B-Instruct、Qwen2.5-1.5B-Instruct和TinyLlama-1.1B-Chat-v1.0，WikiText2采用512历史加512后续teacher-forcing，拟合、验证选择和独立测试分开；每模型三seed各八个paired测试请求。

均值门禁不等于逐请求达标。TinyLlama、$\epsilon=0.002$ 的24独立评估请求中，MeanGate/Upper90/StableSplit分别有10/2/0个请求的观测paired NLL差超预算，平均省略1.667/0.667/0.333MiB；StableSplit约三分之二评估请求回退exact。0/24不是总体风险为零的证明，teacher-forced质量也不等于自由生成正确性。

TableI的Qwen0.5B raw历史KV省略2MiB、33.3%，仍须扣预测器。原式净节省为

$\Delta M=N M_{\mathrm{saved}}-M_{\mathrm{pred}}-M_{\mathrm{aux}},$

其中 $N$ 为共享同模型/同topology预测器的请求数，$M_{\mathrm{saved}}$ 为每请求实际驱逐的历史KV字节，$M_{\mathrm{pred}}$ 为共享预测器，$M_{\mathrm{aux}}$ 为额外辅助驻留，须在同存储层计费。该配置四组FoldedFP32预测器约为单请求省略量的四倍，TableIII每组均值约2.002MiB，不能当精确bank总量。**AI简化算例：**假设共享预测器8MiB、每请求省2MiB、辅助为0，则净省 $(2N-8)$ MiB：一请求反增6MiB、四请求打平、至少五请求才净省。这不是作者精确bank测量。

局部时延在RTX3060 Laptop GPU、batch1、512历史加同一个已知current token，比较从CPU token IDs重放513位置，与从CPU传保留KV、使用已驻GPU预测器重建完整KV再算同一next-token logits。五次预热、每模型八validation请求/每请求30次，按上述模型顺序，Replay/RISK均值60.66/40.09、125.41/48.99、114.07/34.50ms。该1.51/2.56/3.31倍只对这个恢复基线成立，不是与完整KV直接加载、真实无线或所有服务方案比较。之后decode已物化完整cache，不能声称长期GPU净节省。

这在[近似复用边界](kv-cache-mechanism.md#approximate-reuse)之外，具体补上共享预测器摊销、均值风险/逐请求质量及恢复计时义务。尚未核代码、长上下文大模型或真实无线；与[逐请求联合成功](storage-latency-and-slo.md#joint-success)的联系是评价条件，不能由平均NLL或局部恢复时间直接推出联合SLO。

## Direct-storage-and-ordering

**2026-10-26 新增AI候选解释。** [uGDS指定正文](../sources/paper-ugds.md)在远程加载成本之外说明：即使payload由SSD直接经PCIe P2P DMA进入GPU，CPU提交命令、doorbell、完成队列和依赖同步仍能决定有效耗时。uGDS把这些控制放到CPU用户态，预注册移出pinning/地址转换；数据绕过主机staging不等于控制成本消失。

异步入口快速排入host callback，但callback须等上游stream工作完成，再执行I/O并阻塞到DMA完成，才能放行下游kernel。同stream仍严格顺序；独立stream或无相互依赖的批请求才可重叠或乱序完成。跨NVMe、GPU、RDMA的生产者—消费者关系仍由应用events/完成令牌保证，不能因接口叫async就假设任意依赖都已隐藏。

§4.6同16MiB读，单线程同步uGDS/GDS为5.54/5.78GiB/s，单异步stream为5.49/2.36GiB/s。同步接近而异步差异较大，支持检查有效执行路径；不表示物理链路上限提高，也没有独立隔离应用中所有因素。应用平台为A100-SXM4-40GB、Samsung990PRO、PCIeGen4×4/cross-root-port P2P；Qwen3-0.6B、vLLM0.20.1+cu129、LMCache0.5.1.dev35、PyTorch2.11.0+cu129、CUDA12.9，关闭vLLM内存automatic prefix caching、强制SSD-only cache hit。32,768token单请求中位TTFT为1915→715ms，AI复算减少约62.66%；只支持该命中路径，不覆盖miss、混合负载、长期稳定性或质量。

完成方式也有成本取舍。Figure14在一线程/一QP/1MiB时，以发起线程CPU time/wall time计利用率，polling100%变为中断4.15%，时延232.6→245.3μs；中断涉及kernel MSI-X/eventfd/ppoll，不是整机CPU或能耗测量。硬件超时隔离handle并保留潜在DMA资源、等待外部reset是作者设计，未在本库故障注入验证。

接口契约必须与性能一起比较：uGDS解绑目标SSD的kernel NVMe driver，按raw block/aligned offset访问，放弃通常POSIX目录、锁和OS page-cache coherency。cuFile-style入口不证明对普通文件应用语义透明。作者goodput图注为logical KV tokens/s，未见SLO阈值/成功分母，因此不能直接代入[联合服务成功](storage-latency-and-slo.md#joint-success)的goodput。下一步应先核同语义路径、buffer生命周期与完成依赖，再测完整请求；当前不建议据此直接替换生产存储。

## Predictive-prefetch-and-staleness

**2026-10-28 新增 AI 候选解释。** 预取还需知道下一次读哪些状态。[Liu、Xue 的 WorldPager v1 指定正文](../sources/paper-worldpager.md)在长时世界模型中，按匀速外推下一相机 pose，在当前 denoise 期间预取下一 chunk 的历史检索块。控制输入不表示未来动作已经给定；预测错或块未就绪时，系统可复用前一 chunk 的 stale retrieval set。因此其等待减少包含“允许检索内容晚一 chunk”的语义取舍，不能等同于精确原检索集合零等待。反量化仍在 compute stream，不能一并称为已隐藏。

令 $r_{\rm new}$ 为下一 chunk 新读字节，$T_c$ 为可重叠的计算秒数，$B_c$ 为每 chunk 写出字节，$\mathrm{BW}_R$、$\mathrm{BW}_W$ 为有效读、写 B/s。来源的平均模型为

$$
t_{\rm stall}\approx\max(0,r_{\rm new}/\mathrm{BW}_R-T_c),\qquad
\mathrm{BW}_W\ge B_c/T_c.
$$

**AI 单位复算：**取 a_yaw 报告的平均 $r_{\rm new}=121.5$ MB、$T_c=1.25$ s、$B_c=129.4$ MB，十进制读带宽 0.25GB/s 得到读取 0.486s、理想窗口余量 0.764s；持续写需至少 0.10352GB/s。均值留有余量不保证每次都赶上，预测错误、突发复访和读写争用仍可产生尾等待。

RTX 4090 24GB、单 NVMe（顺序读 5.82GB/s）、32GiB cgroup 且无 swap 下，MG2 1.8B 每 chunk 12 帧、四次 denoise，检索三个旧 chunk。仅远端 int4、当前/sink/window bf16，每 chunk 存储由 bf16 486.6MB 减为含 scales 的 129.4MB。两条 synthetic dense-revisit 轨迹各 36 chunks、去一 warmup 后五 rollouts，各 165 稳态 chunks；时间没有置信区间。强制检索块来自 NVMe 的同一 a_yaw 对照为：

| 策略 | 中位 chunk 时间 | 中位 retrieved-KV stall |
| --- | --- | --- |
| WorldPager 预取 | 1255.8ms | 0ms |
| 按需，保留 LRU staging reuse | 1309.5ms | 60.2ms |

后者 chunk 时间约长 4.3%，但这只是指定轨迹/实现；stall 排除反量化、写回，超过 0.5ms 才记为 stalled。软件 token-bucket 限速 0.25GB/s 时，另一 b1_ws 轨迹 median stall 0.03ms、p99 399ms；0.1/0.05GB/s 时，预取 p99 2621/6490ms 还高于按需的 2424/4844ms。均值模型和标题中的 zero 都不提供普遍尾等待保证。

长时容量和记忆质量也分开。3000 chunks 相当于播放 37.5 分钟，但耗时 63.2 分钟、约 9.5fps；该轨迹从未回到已 spilled 的 chunk，不能独自证明长会话读回。另有 2000-chunk 三场景往返读盘测试。600-chunk 往返、五 seeds、每 tier 39 events 中，间隔超过 300 chunks 的 int4 对 bf16 的 MUSIQ 差为 −1.28，95% 事件级 bootstrap 区间 [−2.25,−0.36]（每事件先跨保留 seeds 平均）；短程无可测损失不覆盖长间隔。超过 341 chunks 的 RoPE 表限制另靠重新旋转处理，不能混归因为存储容量。

这在加载成本之外增加“预测能否及时获得、是否改变检索语义”的证据义务。当前未读代码或复现；基线为作者重实现，ReWorld-style 还改了 fallback/bank 条件。应继续做同检索语义的突发复访、真实慢盘、尾等待及长间隔质量对照，暂不推广为 LLM KV 服务或实时生成保证。

## Routing-and-native-prefill

**2026-11-13 AI 候选。** 在多轮任务里，工具返回后路由器可能选另一模型处理下一步。相同历史 token 在当前模型上有 KV，并不保证接收模型能直接使用这份状态。与[跨版本状态移植](kv-cache-mechanism.md#cross-checkpoint-reuse)不同，[ShadowPrefill v1](../sources/paper-shadowprefill.md)由候选目标模型自己把已知历史提前 prefill。实际切换时只计算上次预填之后的缺尾。若状态没有留下，调用走原冷路径。提前执行增加了 GPU 工作和缓存占用，收益依赖是否发生切换、保留了多少状态以及普通流量需要同一设备多久。

完整设计给正常请求的首 token 与生成 token 时延留预算，在观察到排队时停发预填，并允许影子缓存优先淘汰、将仍可用的状态保留到主机内存。限制的对象既包括等待队列，也包括已经在设备上运行的解码批次。后者即使没有排队，也会因预填加入而延长迭代。若预填的模型根本没有被选中，提前计算的 token 也不会被消费。

论文 §6 在总计 16 张 H100 的平台上用 vLLM 回放四组固定模型对和路由轨迹。普通流量为各配置校准容量的 0.3 时，较简单的请求级 Harvest 相对 No Shadow 平均降低切换调用的首 token 等待 61.9%，各任务中 LLM 调用耗时之和平均降低 7.0%。后者不含工具耗时。SWE-agent-LM-7B 与 Qwen2.5-72B-Instruct 的组合只有 13% 的调用切换，平均输出为 249 token。尽管切换调用的首 token 时间降 65.9%，该任务的 LLM 调用时间几乎没变。只有少数调用可以节省预填，而解码时间仍需支付。

该实机实现省略了完整策略的逐迭代预算、专门影子优先驱逐和主机缓存层。附录 D.1 提高普通流量到校准容量的 0.5 后，SWE-agent-LM-7B 与 SWE-agent-LM-32B 组合的全调用时延反而比 No Shadow 高 35.1%，另两组 FusionBench 仍有收益。§5 用 H100 算子画像做的 22 对模拟可比较完整策略，但模拟层普通请求 SLO 或能耗统计应与实机结果分开使用。

这个例子把[预测预取](#predictive-prefetch-and-staleness)的保留条件扩展到另一类资源调度。这里的目标状态由目标权重计算，状态正确性要求与同模型前缀复用一致，代价是先支付可能用不到的计算。比较时需要在同路由轨迹下同时记录普通请求的首 token 和生成时延、切换调用时延、全部 LLM 调用时间及额外预填。模型权重移植与目标预填的研究各自测了不同系统，没有共同负载下的头对头比较。

## Invalidated-kv-and-verification

**2026-11-17 AI 候选。** [Callo v1 §§4–5](../sources/paper-callo.md)给出一个上下文已编辑且预填/解码分离的方案。编辑前的前缀仍可精确复用，编辑后的历史 token 即使位置对齐，旧 KV 仍缺当前前文条件化。解码端按顺序对齐保留的 token，重新旋转键的位置编码，并为新增 token 算临时 KV。预填端同时精确重算失效后缀。这样，等待重算和传输的时间可以用于生成草稿。

预填端在每个分块内逐层写入精确结果，草稿读取暂存和陆续覆盖的状态。收到 prompt KV 已完整到达的确认后，解码端读精确 prompt KV，对草稿执行一次批量验证前向并重算草稿自身 KV。从首次拒绝处起丢弃剩余草稿，提交接受前缀及根据精确验证选出的下一 token。验证要求隔离推测期与提交期的状态。作者在另做的带插桩固定并列规则贪心运行中检查 1,928 次验证与 44,792 个提交 token，未见所列指纹、接受、提交或回滚违规。目标是同次验证前向的 argmax，不同批组成可能改变浮点结果。

同一双 H200 NVL 实测在 52% 基准容量和解码批上限 16 下，按双方都完成的 SWE-agent 回放请求比较，六种模型与保留策略的全请求均时比为 vLLM/Callo 1.05–1.19。该比较包含两项干预。仍用相同传输、只关闭草稿路径的对照显示，批上限 16 时，12%/100% 负载下草稿使全请求均时再降 8%/10%。上限变为 2 且达到此配置容量时，差约为 3%。普通请求共享解码批次，主配置的未推测请求从预填响应到完成的时段平均增加约 2%/6%（轻载与近容量）。

[跨权重状态移植](kv-cache-mechanism.md#cross-checkpoint-reuse)直接让目标模型读旧状态，[目标权重提前预填](#routing-and-native-prefill)提前获得目标原生状态。这里用同目标权重在临时状态上提案，精确重算仍在进行。这个结构允许把暂态近似误差转化为接受率和额外工作，而提交依赖继续落在精确状态上。净收益取决于旧状态是否仍在目标解码端、等待是否够长和解码是否有余量。固定轨迹中的请求均值和有限核验各自回答时延与提交问题，实际会话成功仍须跟踪所有轮次及输出。

## Revisit-similarity-and-quality

**2026-11-04新增AI候选。** [WorldPager的§IV-F/§V增读](../sources/paper-worldpager.md#quality-followup)补上两种评价对象：重访LPIPS比较重访与首次画面的差异，越小表示越相似；MUSIQ另评画面质量。复制得更像与画面更好不是同一个判断。

为比较表示保留了多少记忆收益，作者定义

$$
R=\frac{L_{\rm sw}-L_x}{L_{\rm sw}-L_{\rm bf16}}.
$$

$L_{\rm sw}$ 是无检索记忆滑动窗口的重访LPIPS，$L_{\rm bf16}$ 是全精度记忆，$L_x$ 是待测表示；各项必须使用同一比较口径。分母为正时，$R>1$ 只说明 $L_x<L_{\rm bf16}$，不推出画质更好。**AI算例：**若三项依次为0.30、0.20、0.18，则保留率为120%，表示超出该参照的LPIPS改善，不能改写成质量提高20%。分母接近零还会放大微小差别，应同时保留三个原始LPIPS。

§V的Matrix-Game2.0（MG2，含action modules共1.8B）开发集为6场景、2轨迹、seeds5–9。对称int2的retention为120%，MUSIQ相对bf16差为−4.05，报告区间[−6.44,−2.01]；作者将更低LPIPS解释为复制效应，本轮未独立验证这一因果机制。§IV-F封存测试改用4个新场景、2轨迹、相同seed范围，int4的retention为105%、MUSIQ差−0.06、区间[−0.19,+0.07]。不能把开发集int2与封存测试int4拼成同一配置，也不能把未检出明显损失写成等价性证书。

新增理解是评价轴与归一分母都要保留，不能用超100%的相似性收益抵消画质证据。它补充前节的等待、检索语义和长间隔质量边界；[结论范围解释](claim-scope-and-evidence-synthesis.md#evidence-at-the-same-aspect)说明为什么不同aspect不能相互代偿。代码、原结果与同语义尾部尚未核验，未复现。

## Hybrid-checkpoints

2026-11-03新增AI候选：[Pan等的HiState预印本](../sources/paper-histate.md)研究混合全注意力与循环层模型的跨轮前缀恢复。全注意力需要前缀内全部KV；循环层却把历史压成一个边界状态，末尾状态通常不能裁回更早位置。因此有效命中必须同时满足token前缀匹配和全层状态可恢复。改写或删除中段后保留的尾文本，不会延长精确共同前缀。

若命中位置没有循环检查点，须从更早点重放缺口；没有更早点就重算前缀。AI说明例：旧文本 `abcdefghi` 改为 `abcdeXYZ`，匹配止于e，即使KV保存到e，若循环检查点只有c和i，也应从c重放de，不能把i的状态当作e。这不是论文测量或可逆性保证。[完整状态与分支隔离](kv-cache-mechanism.md#hybrid-state-and-forks)给出另一项相关条件。

不同状态的保留量与一次恢复访问量并不相同。设完整前缀长 $L$、每token KV为 $b$ 字节、一个循环检查点为 $S$ 字节，每 $I$ 个token保存一次且 $L$ 可被 $I$ 整除。在完整前缀恰于已保存边界命中的条件下，KV访问量与保留量都是 $Lb$，循环状态访问量是 $S$、历史保留量却是 $(L/I)S$。于是访问/保留比例为

$$
\rho_{KV}=1,\qquad \rho_{state}=\frac{I}{L}.
$$

例如 $L=32768,I=1024$ 时后者为 $1/32$，约3.1%。这不是所有命中的固定比例：较早边界、缺检查点重放及实际淘汰会改变访问。该不对称说明历史循环检查点可优先放慢盘，恢复时只取一个；更常被完整读取的KV优先快存，快存不足时冷KV也可下沉。原文CPU/SSD加载费用含带宽估计，不当作已测SSD尾时延。

保存得越稀，缺口重算越多；越密，累计占用越大。HiState以均匀未来命中位置等假设和EMA停留时间估计选择间隔，并把中间检查点与末尾KV/terminal状态的淘汰规则分开。只刷新所有历史状态可能保住活跃会话，却挤掉慢会话末尾状态；这种容量取舍不由扩大LRU刷新范围自动解决，也没有全局最优保证。

实验在Qwen3.5-9B、单H100 80GB、约45GiB GPU缓存、96GiB pinned CPU和150GiB disk预算下，最多24 live sessions，回放Weka与TraceLab约三小时请求流。GPU-only基线不含CPU/SSD；使用这些层次的扩展基线匹配相应预算。HiState全请求p99 TTFT相对GPU-only vLLM-Marconi最多改善5.73倍，不能解读为优于所有分层方案同样幅度。

对作者按命中差筛选的reuse-sensitive子集，HiState与`vLLM-Disk*`的平均TTFT为Weka 2.66→1.29秒、TraceLab 1.77→0.96秒。子集定义为`Disk*`比无限缓存命中低至少5个百分点，或与HiState差至少5点；它不是全请求均值，也不能与前述全流量p99拼接。全请求中位数与`Disk*`大体相当、Weka略退，部分请求还会因删尾而退化。正文回放和合成mutation实验均未在本库复现，部署与尾部保证仍待源码和同语义验证。

## Live-migration-and-log-backlog

**2026-11-23 AI候选。** [完整混合状态](kv-cache-mechanism.md#hybrid-state-and-forks)解决一个前缀能否恢复，却没有回答正在输出的请求怎样跨设备延续。[Yu等的新预印本](../sources/paper-gated-deltanet-live-migration.md)将同模型活迁移拆为状态切点、原生追赶和传输积压。它不涉及更换权重后的近似状态移植。

切点应按模型已消费的输入定义。源刚公开 $y_h$ 时，状态只消费到 $y_{h-1}$ ；目的接该状态后，以 $y_h$ 为下一输入，只公开新生成的 $y_{h+1}$ 。循环矩阵、卷积窗口与普通注意力KV要处于同一逻辑边界，否则“最后一个token相同”仍可能拼出不一致状态。

Exact路径不把历史token拼成大批重放。它先prefill并保持同一活请求，再逐个强制输入源已公开的权威token，沿目的原生单token decode追赶；内部算出的输出不公开。相同初态、输入、位置及确定性原生算术支持逐步归纳。作者的16token诊断发现batch32路径已在fused QKVZ投影处分歧，说明相同token序列不足以保证同bit。异构GPU时的参照是目的设备的原生重放，不是跨架构保持源设备逐位输出。

Log路径发送基态与有序的逐token紧凑更新因子，希望将追赶工作转入后台。然而源继续生成时，日志也持续增加。为计算最后必需的包何时离开链路，论文给出FIFO模型

$$
e_i=\max(a_i,e_{i-1})+\frac{b_i}{C}.
$$

$a_i$ 是第 $i$ 包入队时刻， $e_i$ 是序列化离开时刻， $b_i$ 是该包字节数， $C$ 是链路字节每秒；传播、控制与目的重放另计。若每个源token平均产生的新增字节，持续大于该token间隔可传出的字节，积压继续增长；低于链路能力也不保证初始基态留下的队列已清空。后台发送减少前台阻塞的条件，因而不能只由每次更新很小推出。

原文§6.2在相同Qwen3.5-0.8B、双RTX4090、KV-aligned处理下比较Snap和Log，输入及后续长度 $P=D=512$ ，模拟RTT50ms，每项取三次中位：

| 链路带宽 | Snap用户停顿 | Log用户停顿 |
| --- | --- | --- |
| 100MB/s | 353.8ms | 77.5ms |
| 10MB/s | 2.42s | 11.72s |

慢链路下，Log的11.72s中11.37s来自最后必需包尚未抵达。相同数值契约与KV处理仍会发生排名反转，说明增量发送和一次快照的选择依赖到达/服务关系。若改让Exact重算普通KV，比较工作已变化，不能把全请求对照与这张表拼成统一排名。

这些有限实验把“状态更小就迁移更快”的直觉改为可检查的队列条件。评价仍须分开[用户停顿、源释放和期间输出率](storage-latency-and-slo.md#migration-gap-and-release)。作者仅测单请求、两个小模型和模拟链路；本轮未审作者实现或原始日志，真实多请求、故障及随机生成质量仍缺证据，不据此给出生产最优迁移策略。
